# Project 1 — использование

## Что делает проект
Минимальный HTTP-сервер на стандартной библиотеке Go. На любой запрос отвечает одной строкой текста. Цель — увидеть, как устроен самый простой веб-сервер в Go.

## Запуск
```bash
cd project1-hello-web
go run main.go
```
В терминале появится `Server starting on http://localhost:8080`. Остановка — `Ctrl+C`.

## Как взаимодействовать

| Метод | Путь | Ответ |
|-------|------|-------|
| любой (GET, POST, …) | любой (`/`, `/abc`, …) | `200 OK`, текст `Hello, World! This is a simple Go web server.` |

### Браузер
Откройте http://localhost:8080.

### curl
```bash
curl http://localhost:8080/
curl -i http://localhost:8080/any/path      # -i покажет заголовки ответа
curl -X POST http://localhost:8080/          # POST тоже работает — метод не проверяется
```

## Как это работает под капотом
1. `http.HandleFunc("/", helloHandler)` регистрирует обработчик в **стандартном маршрутизаторе** `http.DefaultServeMux`.
2. Шаблон `/` в `ServeMux` — это «всё, что начинается с `/`», то есть он ловит **любой** путь. Поэтому `/abc` тоже отвечает приветствием, а не 404.
3. `http.ListenAndServe(":8080", nil)` открывает TCP-порт 8080. Второй аргумент `nil` означает «использовать `DefaultServeMux`».
4. Для **каждого** входящего запроса Go запускает отдельную горутину и вызывает в ней обработчик.
5. Обработчик получает:
   - `w http.ResponseWriter` — куда писать ответ;
   - `r *http.Request` — всё о запросе (метод, путь, заголовки, тело).
6. `fmt.Fprintf(w, ...)` пишет текст в тело ответа. Статус явно не задан, поэтому Go ставит `200 OK`, а `Content-Type` определяет сам по содержимому (`text/plain; charset=utf-8`).
7. `ListenAndServe` работает бесконечно и возвращает ошибку, только если сервер не смог стартовать (например, порт занят). `log.Fatal` выводит эту ошибку и завершает программу.
