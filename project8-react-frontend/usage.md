# Project 8 — использование

## Что делает проект
Фронтенд на React (Lesson 9): «книжная полка». Приложение загружает список книг из тестового API, позволяет искать по названию или автору и отмечать книги как избранные. Бэкенда нет: роль API играет статический JSON-файл.

## Запуск
Нужен Node.js (проверено на версии 22).
```bash
cd project8-react-frontend
npm install
npm run dev
```
Откройте http://localhost:3000. Изменения в коде применяются в браузере сразу, без перезагрузки (hot reload).

Production-сборка:
```bash
npm run build      # результат в папке dist/
npm run preview    # локально раздать dist/
```

## Как взаимодействовать
- При загрузке страницы полсекунды показывается **Loading…**, затем список из 5 книг.
- **Поиск.** Введите текст в поле — список фильтруется на лету по названию и автору, без учёта регистра. Если ничего не найдено, появится **Nothing found.**
- **Избранное.** Кнопка **☆ Add to favorites** переключает книгу в избранное: карточка подсвечивается, а счётчик **Favorites** в заголовке увеличивается. Повторное нажатие убирает книгу из избранного. Избранное хранится только в памяти и сбрасывается при перезагрузке страницы.

### «API» (запрос, который делает приложение)

| Метод | Путь | Ответ |
|-------|------|-------|
| GET | `/books.json` | массив книг `[{"id", "title", "author", "year"}, ...]` |

Проверить можно при запущенном dev-сервере:
```bash
curl http://localhost:3000/books.json
```
Чтобы увидеть сообщение об ошибке, переименуйте `public/books.json` и обновите страницу.

## Как это работает под капотом
1. **Vite.** Dev-сервер компилирует JSX на лету и раздаёт файлы из `public/` как есть. `index.html` подключает `src/main.jsx`, а тот монтирует компонент `<App />` в `<div id="root">`.
2. **JSX** — синтаксис, похожий на HTML, который превращается в вызовы JavaScript. Выражения вставляются в `{фигурных скобках}`, CSS-класс задаётся атрибутом `className`, а не `class`.
3. **Компоненты** — обычные функции, которые возвращают JSX:
   - `App` — состояние и логика;
   - `BookCard` — отображение одной книги. Данные он получает через **props** (`book`, `favorite`) и сообщает о событиях через функцию-callback (`onToggleFavorite`).
4. **Состояние (`useState`).** `books`, `loading`, `error`, `search`, `favorites`. Вызов сеттера (`setSearch(...)`) говорит React перерисовать компонент с новым значением. Массив `favorites` обновляется иммутабельно: создаётся новый массив (`[...prev, id]`, `filter`), а не изменяется старый, иначе React не заметит изменения.
5. **Загрузка данных (`useEffect`).** Эффект с пустым массивом зависимостей `[]` выполняется один раз после первой отрисовки: `fetchBooks()` → `setBooks`, при ошибке `setError`, в конце `setLoading(false)`.
6. **`fetch`** (`src/api.js`) — встроенный в браузер HTTP-клиент. `res.ok` равен `false` для статусов 4xx/5xx, и тогда мы бросаем ошибку сами, потому что `fetch` их ошибкой не считает. Задержка `setTimeout` в 500 мс имитирует сеть.
7. **Управляемый input.** `value={search}` + `onChange={(e) => setSearch(e.target.value)}`: источником правды для значения поля является состояние React.
8. **Производные данные.** `visible` (отфильтрованный список) не хранится в состоянии, а вычисляется заново при каждой отрисовке из `books` и `search`. Так данные не могут рассинхронизироваться.
9. **Списки и условный рендеринг.** `visible.map(book => <BookCard key={book.id} .../>)`. `key` помогает React понять, какие элементы списка изменились. `{loading && <p>…</p>}` показывает элемент только при истинном условии.
10. **`StrictMode`** в режиме разработки вызывает эффекты дважды, чтобы выявить ошибки. Поэтому в DevTools можно увидеть два запроса к `books.json`. В production-сборке такого нет.
